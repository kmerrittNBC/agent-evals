**Not an emergency for the UI as configured, but worth scheduling an update.** `financial-hq-ui/package.json` pins `@angular/router` to **22.1.7**, and `financial-hq-ui/yarn.lock` resolves that version. It falls within the affected range of the recent [Angular Router SSR denial-of-service advisory](https://github.com/angular/angular/security/advisories/GHSA-57xq-rjx2-v5xh). Updating Angular packages together to **22.2.1 or later** addresses that advisory and the separate [numeric matrix-parameter SSR issue](https://github.com/angular/angular/security/advisories/GHSA-ff3f-86qr-9cv3).

**Urgency depends on SSR exposure.** Both issues require server-side rendering on Node.js/V8. The app build configurations I checked specify browser entry points, not SSR entry points, and `scripts/deploy-static-site.sh` publishes built assets to S3/CloudFront. That makes the described server-side DoS paths unlikely to be exploitable in these deployments. I’d put the aligned Angular upgrade in the normal maintenance queue, not treat it as an incident. If any production deployment renders this UI through a separate Node SSR service, verify that promptly and prioritize the patch.
